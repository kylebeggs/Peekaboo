# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Peekaboo is a macOS markdown viewer app with a Quick Look extension. Both render markdown through a shared local Swift package, `Packages/MarkdownRenderer`.

## Commands

```bash
./Scripts/build.sh      # xcodegen generate + Release build (DerivedData in /tmp/peekaboo-dd)
./Scripts/install.sh    # copy built app to /Applications, re-register QL extension, flush QL cache
```

Tests live in the Swift package, not an Xcode test target:

```bash
cd Packages/MarkdownRenderer
swift test                                          # all tests (XCTest)
swift test --filter MarkdownRendererTests/testTable # single test
```

`qlmanage -p somefile.md` previews via the installed Quick Look extension; `qlmanage -r` resets it after reinstalling.

## Critical: the Xcode project is generated

`Peekaboo.xcodeproj` is generated by XcodeGen from `project.yml`. Never edit the .xcodeproj — change `project.yml` and re-run `xcodegen generate` (build.sh does this). Targets, Info.plist keys, UTI declarations (`net.daringfireball.markdown`), bundle IDs, and signing all live in `project.yml`.

Build products go to `/tmp/peekaboo-dd` intentionally: the repo lives in iCloud Drive, and DerivedData must stay outside the synced tree.

## Architecture

Three layers, dependency flows downward:

1. **`App/Sources/`** — SwiftUI app. `DocumentGroup` opens markdown files (`MarkdownFile.swift`), `DocumentView.swift` renders async, `WebView.swift` wraps WKWebView, `FileWatcher.swift` (GCD dispatch source, 150ms debounce) drives live reload.
2. **`QuickLook/Sources/PreviewProvider.swift`** — sandboxed, read-only QL extension (`QLPreviewProvider`); same renderer, no JavaScript.
3. **`Packages/MarkdownRenderer/`** — pure rendering engine, UI-free and fully testable. Also builds a `markdown-render-cli` executable for command-line rendering.

### Rendering pipeline (MarkdownRenderer.swift coordinates)

Markdown text passes through ordered passes before/after cmark-gfm parsing (`CMarkPipeline.swift`): math extraction (`MathExtractor` → KaTeX via MathJaxSwift), YAML front matter (`FrontMatterPass`, Yams), GitHub alerts (`AlertsPass`), emoji shortcodes, heading anchor IDs, local-image base64 inlining. `HTMLTemplate.swift` assembles the final self-contained HTML: GitHub markdown CSS, highlight.js, and KaTeX fonts are all inlined (base64) so no network access is needed — required for the sandboxed QL extension.

### Constraints to preserve

- **2MB budget** (`expensivePassByteLimit`): documents over 2MB skip math and syntax highlighting to avoid OOM in Quick Look. Don't add expensive passes without respecting this gate.
- **Live reload swaps `<body>` innerHTML** instead of reloading the page, to preserve scroll position. New rendering features that need JS init (like Mermaid) must re-run on body swap — see `WebView.swift`.
- **FileWatcher re-arms after atomic saves**: editors delete/rename on save, so the watcher waits 250ms and re-opens the file descriptor.
- **Mermaid is app-only** (JS in WKWebView); the QL extension renders without JavaScript, so JS-dependent features must degrade gracefully there.
- WKWebView runs with JavaScript minimized — only the Mermaid init hook and body-swap evaluation. Keep it that way.
